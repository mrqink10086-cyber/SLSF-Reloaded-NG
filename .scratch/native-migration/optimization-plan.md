# 原生算法优化实施方案

Status: ready-for-agent

更新：2026-10-28。本文把[优化研究](../../docs/research/native-algorithm-optimization.md)转成已有 A/B/C 任务的实施决定。业务行为按[项目规格](spec.md)，模块接口按[代码库设计](design.md)。01/02 已完成数据基础，后续组按下文接入传播、结算和运行时。

## 采用的方案

| 工作面 | 本次选定的实现 | 归属 |
|---|---|---|
| 地点与地区声望数据 | 实际 LocationId 先查 owner 得到 RegionId；数值行按地区声望数据分配 | A02–A04，01/02 组 |
| 归属绑定 | 数字 canonical owner、父先子后优先级归并、预编译 alias；大地点表稳定键二分 | A04，02 组 |
| 类别集合 | 低 25 位 CategoryMask；按含义分开保存类别设置、关系条件和数值类别汇总 | A02/A03/A07，01/02/04 组 |
| 数值空间 | 连续、实际对齐的 32-double 行；热数值、身份字符串和持久 DTO 分开 | A02/A03/A05，01–03 组 |
| 传播 | 目标入边 CSR；按连续类别执行 AVX2 比较、乘权和 max，独立类别块累加 | A05，03 组 |
| 业务时间 | 一个结算时刻、地区保护期限、批量时间推进；配置先编译成有类型参数 | A06/B07，03/10 组 |
| 等待与刷新 | 三钟源各一份 vector 最小堆；紧凑任务槽、取消代次、dirty 合并 | B01，05 组；事实 adapters 接入 |
| 查询与发布 | 可变模型、公开查询快照、完整 Capture 分开；变更行更新 F，后台批次统一发布 | A03/B02/B05，02/05/06 组 |

保留能跳过整行或整批工作的外层分支。连续数值循环用向量比较与掩码，离散单项命令直接寻址。默认小图先完整扫描全部入边，采用直接 L/R 读取；探针未显示额外预计算一份传播 F 的收益。

FMA/快速数学、指数近似、gather、手写预取、分页快照和增量传播队列留作有具体热点时的选项。本轮实现使用 `/fp:precise`、连续加载和简单公开查询快照；公开结果及原抽样规则是对照依据。

## 01 组：补齐共享约定，沿用公开合同

### A01

公开函数、事件、类别和记录沿用已提取合同。位身份使用现有 FameCategory 规范顺序；旧文档索引、ESP 顺序和公开地点索引通过既有映射转换。

### A02

1. 定义共用 CategoryMask（uint32_t）及有效 25 位常量，提供按类别置位、测试和枚举所需操作；非法类别先校验，高 7 位保持零。置位枚举使用标准位操作，额外 ISA intrinsics 按已选目标能力使用。动态地区集合另用连续的 64 位字数组。
2. 明确 LocationId、RegionId、ApiLocationIndex 的使用面。底层数值命令/查询寻址 RegionId，调用方在 WorldModel 完成公开地点到地区声望数据的转换。
3. 定义实际对齐的数值行：32 个 double、256 字节步长、至少 32 字节对齐；容器分配也满足行类型对齐。补槽实际分配且初始化为零。共享声明放在现有核心头文件，具体布局由 ReputationModel 隐藏。
4. 分开命名外部 provider 事实 DTO 和持久类别设置业务类型，消除 ProviderPort 与 ProviderRegistry 的同名定义；把它们同时包含进一次编译检查。
5. 为正常核心和 ASan 目标安排相同的数值内核编译输入。AVX2 选项作用于数值实现，引导/能力检查代码使用基础指令集；Release 对照使用相同浮点选项。VM 实例目标仍由 C02 补齐。
6. 补齐纯配置 DTO、配置 revision 和有类型更新结果，供生命周期、Configuration 和各消费者共用；JSON/框架对象由 adapters 持有。读取与应用流程按[配置与菜单设计](configuration-design.md)。

交付要求：CategoryMask 应按规范顺序表达类别 0/24，空集、全集及取反结果应限定在有效 25 位；三种类别顺序应按映射转换。调用方应使用各自语义的 ID；行尺寸、步长及容器地址应满足布局约定；共享头应能组合编译，核心/边界应能独立构建。原 A01 合同继续通过原验证器。

## 02 组：完成地区声望数据、集合和发布的数据基础

### A04：先编译世界，再直接查询

1. 保留现有稳定键排序，FindLocation 改为同一比较关系的二分。区域稳定键查找也复用排序索引，日常 ResolveRegion 继续直接查 locationOwners。
2. 将区域 owner 链编译为连续数字索引，以迭代记忆化求出 canonical owner：记录当前路径、检查活动节点、复用已求根，再将整段路径写成同一根。owner 求解时间和辅助空间均为 O(n)，完整绑定另计稳定键排序及 map 校验成本。此项已完成，见[性能修复记录](../../docs/evidence/2026-10-28-region-owner-and-parallel-tests.md)；沿用环、重复引用及未知区域检查。
3. 按父先子后的顺序遍历地点。候选优先级取 `min(priority[声明地区], priority[最终所属地区])`，结果指向最终所属地区，再执行 `best[node] = min_by_priority(candidate[node], best[parent])`，保持原注册顺序的优先级。
4. 绑定时生成排序的“规范化 alias → ApiLocationIndex”表。请求只规范化输入一次；重复 alias 和原 customOrder 索引继续按现有约定处理。
5. 多个室内/子地点共享 owner 地区声望数据。区域修改准备新映射和行迁移表，状态按稳定区域身份迁移，再一次提交；LocationId、RegionId 重新编号后仍以稳定区域身份绑定存档地区声望数据。

当前 DFS entry/exit 记录进入/离开时钟，父先子后归并单独保存遍历顺序。先交付上述绑定路径；BuildLocationIndex 的重复 map 和逐节点 children 分配按加载测量的热点占比决定是否改为连续 children offsets/indices。

交付要求：森林/归属应通过既有参考对照，并覆盖全局优先级与最近祖先不同、嵌套 owner、跨树、深链、alias 规范化及 customOrder 重排。缺少 parents 数组的构建入口应按既有约定处理；有序查找应覆盖命中、未命中及排序边界。

### A03：每个地区的声望数据、类别集合与公开查询快照

可变状态保存 L/R、当前 F 和必要业务字段。公开查询快照包含 F、公开 flags、对应身份映射及 revision/epoch；Capture 取得完整存档数据。单项 Set→Query 只重算目标地区，通过各类地区数量增量更新类别汇总；ClearAll/Wipe、恢复和重新绑定按批量路径重建。后台同批操作在批末发布，快照复制成本按实际载荷记录。

| 集合 | 生成与消费 | 更新时机 |
|---|---|---|
| 地区声望数据 positiveMask | 由公开 F > 0 派生，用于旧“存在正声望”查询/跳过 | 所有实际数值写入后 |
| 本地衰减候选 | 从 L > 0 取得，外层再检查地区保护 | A06 使用时生成，或随 L 更新缓存 |
| legacySpreadableMask | F 达到旧来源门槛的缓存，仅供确有需要的旧语义消费者 | 有消费者时维护；门槛变化重建 |
| 模组类别 mask | 每个模组启用的类别；activeCounts 记录启用各类别的模组数量 | 注册/撤销时按变化位增减，计数归零时清汇总位 |
| 公开/内部显式 flags | 保留当前 SetFlag/ClearFlag 独立含义，B06 核对对应输出合同 | 对应 flag 命令 |
| 事件候选、朋友/恋人禁令 | A07 按实际入口生成/编译 | 事件或配置变化时，04 组实现 |

这些集合各自命名。positiveMask 表示 F 的性质；L 衰减读取 L 的资格；新传播门槛在乘边权之后判断。SetFlag/ClearFlag 的存储也与这些派生值分开。区域 dirty 集合标记需要重算/发布的地区声望数据，R 仍有待推进变化时继续处理。

mask 与数值在同一提交内更新，Set/Clear/Wipe/批量结算都走同一维护路径。提供者撤销仅减少自己的计数；NotReady/Stale 保持原类别设置和计数。四类清理继续由完整业务条件决定。

交付要求：同一所属地区的地点共享声望，独立地区保存各自声望；重新绑定时按稳定地区身份迁移数值。Set/Clear/Wipe 同步更新类别汇总。注销只移除该模组的类别设置，暂时未知及恢复期间保留设置和计数。每个公开查询快照包含同一次更新的映射、数值和配置版本，已取得的快照保留当时内容。具体用例按 02 组执行。

### A08：保存业务值，重建运行期索引

继续保存稳定区域身份、L/R、持久 flags、类别设置、模组区域注册及实际业务时间字段。用户配置和用户连接偏好保存在跨档 JSON；当前 v1 的 settings/用户 graphEdits 在接入时明确版本处理，恢复以当前配置为准。owner/alias 索引、CSR、派生类别集合、dirty 集合和堆由绑定/恢复阶段重建。运行期布尔布局与持久 schema 分别演进；持久字段含义变化时应修订 schema，并保留现有 v1 夹具及其版本处理用例。地区级保护及注册身份映射按代码库设计衔接。

交付要求：Capture→Encode→Decode→Bind/Restore 应恢复捕获的业务值和类别设置，类别汇总应由恢复后的业务及当前配置重建。公开索引/加载顺序重排后应按稳定身份找到同一地区声望数据。激活应采用当前跨档 JSON，并按 codec 版本规则处理 v1 settings/用户 graphEdits；无效字节流应由实际 codec 返回校验错误。

## 后续组如何接入

### 03 组：A05/A06 传播与结算

- CSR 连续保存目标 offsets、来源 RegionId 和权重；每目标遍历全部入边，类别块使用独立累加器，输出 incoming 行只写一次。直接读冻结 L/R，推进 R 使用另一个输出阶段。
- 采用全类别连续 AVX2；离散显式更新直接寻址。存在动态选类的批次时先用 mask 筛选，再按实际工作选择置位枚举或向量 lane mask；需要 AVX2 lane mask 时共用 16 项 × 4 个 64 位 lane 的 512 字节表。稀疏枚举与连续向量执行的切换按实际批次成本选择。
- 本地衰减在外层按地区保护及 L 候选跳过；传播按待处理变化选择工作，R 按传播规则独立推进。乘权后逐类门槛在内层比较；来源下降、边关闭、替代来源及 R 退去仍比较全部入边。
- 将共同时间系数移出类别循环，类别倍率和档位参数从有类型数组读取。保留旧 DecayFame(d) 每个合格格抽一次、再乘 d 的批量含义，以及默认/自定义地区差异。任务按必要业务边界调度，批次消费期间的实际经过时间。

03 组现已接入 `PrepareSettlement`：准备结果拥有 owner 投影后的 CSR、类别倍率/档位数组和按 RegionId 排列的自定义地区标记。地区绑定、连接、配置或自定义地区注册改变时替换准备结果，普通声望更新继续复用。`AdvanceInputs.prepared` 消费只读准备结果；原 graph/configuration 入口通过工作缓冲缓存，并按源内容变化刷新。后者仍比较源内容，正式会话接入使用准备结果。

`SettlementWorkspace` 由统一执行器复用数值 staging、来源行、incoming、经过时间和命令排序缓冲。到期命令按业务时间分段，先结算到该时间，再应用命令，最后结算到 now；同一时间保持入队顺序。远端松弛使用独立 AVX2 TU，标量路径保留为回退和对照。完整结果见 [03 组报告](../../docs/evidence/task-groups/03-diffusion-and-settlement.md)。

完成标准：既有传播/结算行为用例通过；标量与 AVX2 比较有效类别、补槽、门槛两侧及公开整数结果。检查 Release 汇编的连续加载、独立累加器和循环内 spill；记录完整结算与发布成本。

### 04 组：A07/B04 实际候选与采集

关系、配置和已知事实先组合成入口自己的候选集合。自动目击保留原候选顺序、随机调用顺序、selectedMask 去重及最多 50 次尝试；动画和显式写入按各自规则处理。readiness 附在实际依赖的事实，部分未知只暂停依赖它的候选。

交付要求：候选集合应与直接逐类规则一致；固定随机序列应保持候选顺序、调用次数和最终计分类别，包括重复抽取导致不足额的场景。设备/外观 dirty 应在刷新时点批量采集，计分由实际业务事件及原周期驱动。

### 05/06 组：B01/B02/B05 等待、提交与保存

三种钟源分开维护 vector 最小堆，堆中只放 deadline、任务槽和代次；重对象放在槽表。按到期顺序处理本轮任务，同期限有稳定的入队顺序，跨钟源按各自域判断到期。取消失效任务在取出时检查代次，并处理连续取消下的容器回收。

会话执行器合并同目标 dirty 请求，一批事实供规则顺序消费。同步公开写入返回时完成新 revision 发布；完整 Capture 复制后在锁外编码。

交付要求：生产调度入口应按各钟源判断到期及暂停，按代次处理取消并校验 epoch；同批同目标刷新应合并，实际业务事件应逐个消费。发布应关联同版本映射与数值，Capture 应取得完整持久字段；WakeSource 应完成目标游戏 probe。

### 10 组：B07/C08 配置编译与消费

按[配置与菜单设计](configuration-design.md)统一读取跨档 JSON，用更新通知发布有类型的类别参数、关系 mask 和图参数，热循环读取编译结果。阈值修改在同一次候选提交中重建所需资格集合；菜单逐帧读取公开查询快照，旧公开 JSON、本档保存和用户配置使用各自合同。

交付要求：配置提交应同时应用新参数、阈值资格集合、关系 mask 及图；修改/关闭、UI 配置刷新和游戏重载应读取当前跨档 JSON。无效配置应返回具体错误并保留有效值；菜单及旧文件应沿用公开合同中的身份。
