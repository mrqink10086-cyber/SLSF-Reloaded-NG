# SLSF Reloaded NG 0.1 项目规格与实施路线

Status: ready-for-agent

更新：2026-10-30。本文是原生迁移的项目入口，统一范围、已确定的行为、实施顺序和完成标准。[代码库设计](design.md)负责模块、接口和状态归属；[算法优化实施方案](optimization-plan.md)负责已采纳的数据布局和执行方式；[配置与菜单设计](configuration-design.md)负责 JSON、更新通知及跨档设置；任务说明负责具体步骤，研究记录负责源码依据，测试报告负责说明已验证的结果。

## 问题

旧版用 Papyrus 承担声望、地点、扫描、计时和外部模组查询，更新成本高，业务状态分散。迁移需要把这些工作交给 C++，同时让读取声望、类别、Global、文件及事件回应的下游继续使用原有接口。

此前的方案又散落在研究、设计、总计划和分组任务书中，重复写规则，也把候选算法和验证实验写成了交付要求。实现者难以判断什么已经确定、什么已经完成。

## 解决方案

以 C++23/SKSE 插件保存并计算业务状态。Papyrus 保留公开调用入口和必要的事件、框架数据传输。菜单、公开 API 和自动业务使用同一份状态及命令入口。

兼容以公开功能和协议为边界：保留声望类别、查询含义、函数签名、事件载荷和输出身份；内部布局、调度和算法按本规格实现。除已选定的传播重写和明确的旧错误修复外，玩法以原脚本为基线。

目标环境为 Windows x64、SkyrimSE.exe 1.6.1170、SKSE 2.2.6、C++23、MSVC/Xmake 和仓库固定的 CommonLib。集成基线为 SexLab P+、DDNG；配置界面使用 SKSE 菜单。

## 用户故事与需求

1. **公开查询**：作为下游作者，我希望继续查询原有 25 类声望、地点和 flags，以便原脚本继续取得有意义的结果。
2. **公开写入**：作为下游作者，我希望 Set、增减、Clear、Wipe 和注册操作保留各自含义，并在同步调用返回后立即查询到新值。
3. **事件协议**：作为下游作者，我希望原有 52 个输入事件和 7 个回应的名字、类型、参数顺序保持一致，以便未重编译的客户端继续通信。
4. **公开资产与数据输出**：作为模组使用者，我希望原插件记录、脚本实例、地点声望 Global、匿名/评论许可和既有文件输出继续服务对话及其他模组。
5. **模组启用类别**：作为模组作者，我希望 SLSF 分别保存每个模组启用的类别。同一类别只要仍有一个模组启用就保持有效；注销时移除该模组自己的设置。
6. **暂时未知**：作为玩家，我希望外部数据暂时 NotReady/Stale 时保留模组注册和类别设置和已有声望；依赖该事实的新计分暂停，正常时间规则继续，恢复后不追补未知时段。
7. **类别清理**：作为玩家，我希望 Cum Dump、Unfaithful、Cuck、Airhead 在确认内置来源不存在且外部启用类别设置全无时，按原规则每个失效阶段清理一次。普通类别保持自己的数值规则。
8. **地点归属**：作为玩家，我希望城市、室内和子地点按原归属规则共享地区声望；独立注册的地区保存自己的声望。
9. **自动传播**：作为玩家，我希望声望沿显式区域连接持续传播，每跳减弱，低于门槛停止；同类多来源取较强者，来源下降后外地传闻逐渐退去。
10. **自定义连接**：作为玩家，我希望在菜单连接独立区域并保存选择；未连接区域显示为孤立。
11. **原有玩法**：作为玩家，我希望增长、衰减档位、匿名、目击、动画分类和评论规则沿用原有体验，并采用传播模型所需的调整。
12. **时间推进**：作为玩家，我希望睡眠、等待和快速旅行推进传播、衰减及匿名记忆；检测刷新保持原计分节奏。
13. **场景与外部状态**：作为玩家，我希望计分使用 P+ 的实际角色和交互、DD 设备及已应用纹身，按原分类规则得到对应声望。
14. **原生存档**：作为玩家，我希望 NG 新档中的声望、注册、区域和业务时间在保存、重载、退出重进及加载顺序变化后按稳定身份恢复，各存档独立。
15. **配置与转移**：作为玩家，我希望菜单设置和用户连接偏好保存在 SKSE/Plugins 的 JSON 中跨存档使用，菜单修改/关闭、UI 配置刷新和游戏重载时读取生效；原有公开 JSON 继续用于相应数据转移，失败导入保留原状态。
16. **性能**：作为玩家，我希望常用查询和更新使用数字索引、紧凑数据与批处理，减少字符串查找、重复外部查询和等待开销。

## 实现决定

### 代码与注释交付要求

所有分组遵守仓库 [AGENTS.md 的代码注释规则](../../AGENTS.md#code-comments)：默认零新增注释，拿不准就不写；仅保留该规则允许的必要例外。此项适用于实现、头文件、测试、脚本及生成模板，交付前检查本次新增或修改的注释。

### 需求实现与业务算法

- **声望数据与设置**：C++ 模型保存本档声望和运行状态，Global、StorageUtil、状态 JSON 和菜单显示使用更新完成后的值；用户设置从配置 JSON 统一读取。原公开记录身份及实例/Global 调用方式按已提取合同保留。
- **显式数值命令**：各入口保留各自边界。直接 Set 应支持完整 Int32。双层状态中，公开新值 V 写成本地 L=V、传入 R=min(R,V)，查询值 F=max(L,R)。Clear/Wipe 应清指定范围两层值；局部清零后继续处理将来实际传入的影响。
- **手动传播**：保留明确源、目标、类别和百分比；来源小于 10 无操作，百分比 clamp 到 10–100。目标按旧目标加来源百分比计算、最后截断并封顶 150。修正旧整数除法错误：来源 100、目标 20、30% 得到 50。
- **自动传播**：地点父子树处理归属，显式有向图处理传播。每条有效边保留系数在 0 与 1 之间，0 关闭边；跨边后低于门槛的候选被丢弃。同目标同类比较全部入边取 max，例如 25 和 20 得到 25。被动传入保存在 R，可中转；本地实际行为和显式命令建立 L。
- **时间与衰减**：L 应以旧版增长/衰减、地点保护和相关配置为基线，保留默认与自定义地区差异。地点保护由本地增长续期，R 随传入目标独立增长或退去；同一区间应消费一次。结算应按本地衰减→传播的顺序提交 L/R，再派生 F。
- **兼容 Spread/SpreadRoll**：先结算实际经过时间，再从同一快照执行一跳脉冲；受影响目标比较全部入边，R 取旧 R 与候选的较大值。本次调用只走一跳。
- **原玩法基线**：保留夜间与前戏同时成立才减半、原匿名记忆公式、固定身体槽位/Keyword、关系分组、一次扫描最多一次成功、评论限制和原动画开始宽限。P+ 的明确事实替换旧推测；刷新更新事实，实际业务事件及原周期驱动计分。
- **未知与清理分离**：适配器 readiness 与本档注册是两类状态。暂时未知只影响依赖事实的新业务；确认提供者失效才撤销其类别设置。核心可输出四类待清理集合，业务层同时检查内置来源条件，再执行一次清理。
- **跳时**：消费真实经过的游戏时间，按业务边界处理衰减、传播和记忆；排队命令早于已消费时刻时，在已消费时刻应用，后续区间使用新值。目击/评论只处理实际观测到的事件。
- **配置与保存**：`Data/SKSE/Plugins/SLSFReloadedNG.json` 保存跨存档设置及用户连接偏好，Configuration 统一读取、编译并通过有类型更新通知交给各模块。菜单编辑完成/关闭、打开或刷新配置页、新游戏及游戏读档/重载触发读取；逐帧渲染使用缓存。原生存档保存稳定身份、L/R、保护、已结算时刻、类别设置及区域注册；加载使用当前 JSON，完整绑定后激活。具体流程见配置与菜单设计。

### 算法工程与执行优化

以下工程选择用于实现上述行为：

- 每个 RegionId 保存一份地区声望。WorldModel 预先生成地点归属和别名映射，稳定地点大表使用有序索引；公开地点索引和存档稳定身份分别映射。
- 每个地区的 L/R 各用一行连续 double 保存：32 槽中使用 25 类，行宽 256 字节、至少 32 字节对齐。double 精确保留 Int32 Set，填充槽初始化为零并从业务计算中屏蔽。模组类别、关系条件、事件候选和数值资格分别用低 25 位类别集合表达。
- 传播边按目标组织为 CSR；AVX2 在类别行内执行乘法、门槛和 max。同一步读取冻结 L/R，统一写回。外层跳过整批无工作，内层使用连续类别块。
- 原生数值写入使用短锁事务，完成提交后返回；外部事实在锁外、合法引擎上下文取得。可变状态、公开查询快照和完整保存 Capture 分开，变更行维护 F；查询和菜单读取同一 revision 的身份映射与数值。
- 一个执行器拥有协程和业务边界工作；三种钟源各用连续期限堆，任务槽保存重对象；同目标 dirty 请求合并。游戏时间、排除菜单的现实时间、包含菜单的现实时间分别计时。
- 发布版使用单一 AVX2 路径；基础指令集引导代码先检查 CPU/OS 支持，再进入扩展指令代码。
- 静态地点表和进程 API 描述在进程内复用；角色、场景、VM/JC 句柄及等待任务按存档会话更新。异步消息附会话/索引/场景代次。
- 传播推进先采用满足上述行为的直接实现，选择并记录有效默认权重、门槛和时间参数。指数松弛、特殊收敛处理及更细数值实验是遇到具体问题时的工程选项。
- 用相同输入检查优化前后结果和成本；性能测量用于定位实际瓶颈。交付应满足上述玩法、公开结果及执行成本要求；数值实验按具体算法问题选择。

具体布局、mask 语义、时间抽样和分组验收统一见[算法优化实施方案](optimization-plan.md)。内部 flags 继续按各入口合同处理，数值类别汇总分别维护。

### 外部边界

适配器只提供自有数据快照。P+ 默认经公开 VM 方法异步读取；DDNG 使用已验证的 v2 能力，RaceMenu 使用接口交换，SlaveTats NG 接收一次性广播并按 JC 所有权规则复制数据。启动时先注册必要监听，实际数据按需查询。

接口描述的 Available、角色数据的 Ready、公开模组注册和类别设置分别管理。进程检测和存档切换按对应生命周期处理；P+、纹身或设备能力缺口以具体状态传递给业务。

## 测试决定与完成标准

主要测试边界是公开命令/查询及其可观察状态。已有核心测试通过这些入口检查数值、注册、地点和保存；扩展模块沿用这个边界。引擎、VM、提供方 ABI 和 PEX 兼容由对应边界测试及目标游戏验证。

| 验收面 | 需要看到的结果 |
|---|---|
| 核心行为 | 同步返回后读到提交值；直接 Set 精确保留 Int32；暂时未知保留模组类别设置，四类按完整条件清理一次；保存、加载和地点重绑定后恢复同一地区的完整声望 |
| 布局与集合 | 同一 owner 应共享地区声望数据；mask 应可由业务值重建；行应满足对齐/补槽约定；发布应关联同一 revision 的映射、数值及配置，持有快照应保留发布内容 |
| 传播与时间 | 每跳应应用权重和门槛，25/20 应取 25；来源下降后应比较剩余入边；同一区间应消费一次，观测计分应处理实际事件 |
| 公开兼容 | 原声明编译的冻结客户端 PEX 在替换提供方后运行，函数/事件/类别/资产及 Global、StorageUtil、JSON 输出符合合同 |
| 生命周期 | 新档、保存重载、退出重进、A→B 及加载顺序变化应按稳定身份恢复各档业务；加载应在完整绑定后激活，回调应校验会话及场景 epoch |
| 配置 | 修改完成/关闭、UI 配置刷新和游戏重载应读取当前跨档 JSON；各档业务应独立恢复，各模块应同版本应用配置，逐帧渲染应读取缓存 |
| 集成与菜单 | P+、DDNG、纹身/外观查询、菜单操作在指定版本实测；缺失/未知能力的行为符合需求 |
| 性能与内存 | 热查询、结算和 dirty 刷新成本有记录；相关 ASan 检查通过，实际解析器有坏输入用例 |
| 注释 | 本次新增或修改的注释均符合 AGENTS.md 的必要例外；无例外时零新增注释，不能以注释数量作为完整性指标 |

真实下游 MOD 联测可补充问题线索；当前发布验收以完整公开协议、冻结客户端和输出检查为准。测试量随修改风险确定，既有随机/模糊测试保留；新的模块以能暴露具体错误的用例和必要对照为主。

命令和测试工具见[测试说明](../../docs/superpowers/plans/2026-10-27-task-books/00-native-testing.md)。进度依据各组报告及[05/06 审核修复](../../docs/evidence/2026-10-29-05-06-fixes.md)。当前已接生命周期消息和 SKSE 序列化回调；生产执行泵、JSON 文件读取及目标游戏完整交互仍待接入/验收。

自动核心/边界测试按逻辑 CPU 多进程分片，固定 seed 分散重用例并单次输出控制台/JUnit；`-Jobs` 控制并发。owner 长链及完整 ASan 的当前成本见[性能修复记录](../../docs/evidence/2026-10-28-region-owner-and-parallel-tests.md)。游戏运行时沿用统一业务执行器。
