# 05/06 审核修复与等待项退休优化

日期：2026-10-29。基线：`184c964eb226f614169a6b582c3adbd9970a04af`。本次关闭[独立审核](2026-10-29-05-06-adversarial-audit.md)的 L1/L2、S1–S3，并优化等待项退休。原审核及其探针保持历史内容。

## 修复行为

| 审核项 | 修改后的行为 | 回归覆盖 |
|---|---|---|
| L1：宿主加载失败仍激活 | `kPostLoadGame` 将 `message->data != nullptr` 作为宿主结果传给 `ActivatePrepared`。失败调用 `RejectPreparation`，关闭业务、detach 并丢弃候选；重复激活和 Attach 失败也完整关闭 | 有效存档 prepare 后收到 false；后续健康加载；重复激活时取消旧等待 |
| L2：light plugin 稳定键含加载索引 | `BuildStaticWorld` 使用 CommonLib 的 `GetLocalFormID()`。解码后按当前插件表的 `IsLight()` 迁移历史错误的 24 位键，覆盖地点、自定义地区及旧 graph edit 端点 | 旧键恢复数值 37.5，覆盖 v1/v2；完整插件和暂缺插件原样保留；迁移幂等；归一化碰撞拒绝加载 |
| S1：协程异常 abort | promise 保存 `std::exception_ptr`，异常完成该 flow；调用方可用 `Flow::Failure()` 读取。其他到期任务继续执行 | 初次执行、Delay 恢复、CancelWait 和 Detach 恢复后抛异常；Failure 可重新抛出为原异常 |
| S2：loaded/pending 被终态缓存 | `pending` 优先评为 `Waiting`，下次 Ensure 重试；同样适用于已加载或暂时看似完整的 API | `loaded=true,pending=true` 后就绪，第二次查询得到 Available；pending 的完整 probe 仍为 Waiting |
| S3：provider 查询依赖环死锁 | 记录每个查询线程和线程等待边，在 CV 等待前检测同线程和跨线程环；导致成环的内层调用返回 Incompatible，外层 provider 仍决定自身结果 | 同 ID、A→B→A、barrier 同步的双线程互相依赖；合法 sibling 查询和既有并发重复查询仍通过 |

SKSE 的加载 bool 编码在指针值中，未解引用该指针。迁移只接受当前元数据确认的 light plugin，包括带 ESL 标志的 ESP；暂缺插件保留其 unresolved 数据，待插件再次出现时迁移。归一化后冲突交给 Restore 的重复键校验拒绝，不合并两份声望。保存格式及 codec 版本保持不变。

关键实现：[Dispatcher](../../src/runtime/Dispatcher.cpp)、[Flow 合同](../../include/slsf/runtime/Dispatcher.h)、[Lifecycle](../../src/runtime/Lifecycle.cpp)、[SKSE 入口](../../src/main.cpp)、[稳定键迁移](../../src/persistence/StableKeys.cpp)、[CapabilityRegistry](../../src/integrations/CapabilityRegistry.cpp)。

## 等结果优化

旧 `RetireWait` 每次对等待向量 `erase_if`，连续退休 W 项会重复扫描，形成 O(W²)。现在使用 `std::list<shared_ptr<WaitEntry>>`，每项保存自己的迭代器，退休直接 erase，单项移除为 O(1)。插入顺序、Detach 恢复顺序、单赢家的 live 标志及锁外 resume 保持原语义。整个定时到期批次仍包含期限堆操作，复杂度为 O(W log W)。

在同一机器以 MSVC `/O2 /MD` 链接当前 Core，复用[原探针](review-05-06/wait-retire-probe.cpp)，每规模五轮取中位数。等待项创建不计入计时；到期包含 Step、定时器回调及协程恢复，取消包含 Scheduler 取消及协程恢复。

| 等待项数 | 同时到期：旧 → 新 | 逐项取消：旧 → 新 |
|---:|---:|---:|
| 100 | 28 → 31 µs | 12 → 10 µs |
| 1,000 | 415 → 222 µs | 292 → 103 µs |
| 5,000 | 6,918 → 1,194 µs（5.79×） | 6,573 → 603 µs（10.90×） |

全部轮次的完成数、顺序及 checksum 与旧实现相同。新增混合 512 项回归还覆盖部分取消、到期后重新等待、Detach 依序恢复以及不重复恢复。新实现每项增加链表节点分配和迭代器，创建成本及额外内存不在上表计时中；100 项到期略慢，数千项批量退休明显改善。没有真实游戏等待数分布，本表反映合成负载。

原始结果：[优化前](review-05-06/wait-retire-probe.stdout.log)、[优化后](fix-05-06/wait-retire-after.log)。复跑使用 `review-05-06/run-probes.ps1`；其中其他探针保留历史缺陷断言，不能把子进程旧预期退出码当作修复后验收标准，修复验收以当前回归测试为准。

```powershell
xmake build -y -j8 SLSFCoreTests SLSFBoundaryTests SLSFReloadedNG
xmake build -y -j8 SLSFCoreTestsAsan SLSFBoundaryTestsAsan SLSFDispatcherOfflineProbe

```

- ASan 正常探针及预期越界的负对照、随机/差分用例、基准均通过工具脚本检查。
- StateCodecFuzz、SerializationFuzz 各 100,000 次，seed 1170，无失败。
- 离线唤醒：3,600 帧、模拟 60 秒，长等待 1,000,000 秒，completions=3、stale_callbacks=0、最大 pump=2.9 µs，PASS。

日志：[完整检查](fix-05-06/native-tests.log)、[SerializationFuzz](fix-05-06/serialization-fuzz.log)。生产执行泵、真实 JSON source、DDNG 设备业务及游戏内端到端验收继续按原项目分组完成，本次测试不替代这些集成验收。
