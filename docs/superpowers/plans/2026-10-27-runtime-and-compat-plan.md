# B：运行时与兼容输出任务说明

[项目规格](../../../.scratch/native-migration/spec.md)定义行为，本文件说明运行时如何接入核心，以及公开输出如何继续服务客户端。模块归属见[清单](2026-10-27-task-books/manifest.json)。

模块接口、会话归属及提交/发布路径按[代码库设计](../../../.scratch/native-migration/design.md)。公开 adapters 共用 Session，事实采集及文件解析在事务锁外完成。

期限结构、dirty 合并、公开查询快照和配置编译的采用方案见[优化实施方案](../../../.scratch/native-migration/optimization-plan.md)，由本文件对应任务接入。

## B01 时钟、唤醒与调度

实现游戏时间、排除菜单的现实时间、包含菜单的现实时间三个钟源，以及 deadline 队列和统一执行器。协程表达 3/5/10 秒等流程等待；取消与等待资源由 RAII 管理。

每钟源使用一份 vector 最小堆，紧凑堆项引用任务槽及取消代次。按到期对象工作；同目标 dirty 刷新合并，业务计分事件保持各自含义。

用离线 EXE 模拟 SKSE AddTask 主线程队列，以真实 Dispatcher 验证长等待、菜单暂停、无输入心跳及加载换代。等待应登记期限并交还主线程；约 1 秒的装备 dirty 合并、30 秒提示和原业务计分周期各自调度。B03 将一次性 AddTask 投递接入游戏生命周期。

交付要求：假时钟应验证到期、取消、暂停及同期限顺序；离线 EXE 应在长等待期间持续执行主线程心跳，并验证菜单时钟、取消、会话切换和停止唤醒；统一执行器应管理协程帧，加载切换及退出应释放对应等待任务。

## B02 同步事务与发布

数值命令在短锁内完成校验、结算、修改及 revision 发布，返回后查询可见。事务只处理自有数据；引擎、VM、文件和第三方查询在锁外完成，异步等待交还执行器。

引擎消息及异步结果拥有自己的参数，附 session/index/scene epoch，提交前核对有效性。每次发布应以同一 revision 关联身份映射、数值及已应用配置；读者持有的快照应保留其发布内容。

接入 02 组已拆分的可变模型与公开查询快照，变更行维护 F，后台同批操作统一发布；同步公开命令返回时完成发布。完整保存 Capture 另走全量持久 DTO。

交付要求：连续 Set→Query 应读到提交值；并发读和嵌套回调应读取完整发布版本；异步结果应通过 epoch 校验后提交。同步数值命令应在本次调用内完成数值事务，外部数据输出应在事务外执行。

## B03 生命周期与装配

一个 composition root 连接 core、engine、runtime、ports、API 及集成。DataLoaded 建立可复用静态索引/进程能力；NewGame、PreLoad、Load、Revert、失败加载和返回菜单切换会话状态与业务开关。

基础指令集引导代码检查 CPUID、OSXSAVE、XGETBV 后进入 AVX2 路径。启动读取配置；新游戏和每次读档/重载通过 Configuration 重读 JSON，以当前设置绑定本档业务后统一激活。06 组先用 A02 配置接口和可控 adapter 接线，10 组接实际 JSON 实现。

交付要求：新游戏、同档重载、A→B、加载失败和返回菜单应记录业务开关及 epoch 变化；完整绑定后应开放业务，失败加载时应保持业务开关关闭；监听应在一次性提供方广播前注册。生命周期细节见[设计](../specs/2026-10-26-integration-state-lifecycle-design.md)。

## B04 引擎事实查询

收集已加载 ESP/ESL、稳定记录身份及 Actor/装备/关系/位置快照。查询在合法引擎上下文执行，结果复制为核心 DTO。

在目标运行时验证实际关系等级 `-4..4`、感知/LOS、距离和每 NPC 可见性。业务读取运行时关系；静态关系记录的 `0..8` 编码只作接口核对。安装情况、动态状态及未知分别表示。

交付要求：1.6.1170 probe 应给出接口、调用上下文和 unknown 返回条件；核心规则应使用相同 DTO；持续查询应覆盖当前业务所需 Actor。

## B05 SKSE 保存与加载

使用独立四字符记录 ID 和版本接入 Save/Load/Revert。编码复用 A08；加载先解码，再通过当前插件表与 FormID remap 绑定稳定身份，最后一次激活。

保留 unresolved 引用以便诊断，保存流写入本档业务状态。加载应在完整绑定后激活；失败加载应维持业务开关关闭并报告绑定结果。

交付要求：保存重载、退出重进及加载顺序变化应按稳定身份恢复本档注册、区域和声望；缺失记录、截断及未知版本应返回对应加载结果。新会话应采用当前跨档 JSON 的设置和用户连接偏好，并按 codec 版本规则处理 v1 settings/用户 graphEdits。

## B06 公开入口与兼容数据输出

用单一 PublicApi 承载原公开函数及事件命令。Papyrus facade 保留原实例/Global 声明；typed ModEvent 通过薄 PSC 传输，普通原生事件按其独立协议处理。输入完整复制后交给核心。

先补齐输出合同：25 类 Reloaded Global、评论/匿名 flags；旧地点 StorageUtil 的 20 类 × 24 索引、原拼写 key；原始 `SexLab - Sexual Fame [SLSF].esm` 的 Global/配置桥接。逐项记录 key、index、类型、目标记录、更新时间和依赖条件。`SLSF.LocationsFame.PC.Beastiality` 等公开拼写保留。

数据输出从已提交 revision 生成，输出端应按 session epoch 校验、revision 顺序应用。分类及未知返回值遵循公开合同。

交付要求：替换提供方前应使用旧声明编译并冻结客户端 PEX；替换后应运行函数/52 输入/7 回应探针，比较返回、载荷、记录绑定及各类数据输出。真实下游联测可补充兼容证据。

## B07 配置、连接和 JSON

按[配置与菜单设计](../../../.scratch/native-migration/configuration-design.md)实现 Configuration 模块，以 `Data/SKSE/Plugins/SLSFReloadedNG.json` 保存跨档设置和用户连接偏好。统一处理 Reload、Update 和不可变快照，以有类型更新通知传给模块；JSON 只解析一次，各消费者读取编译结果。

菜单编辑完成/关闭、打开或刷新配置页、初始化/新游戏/游戏读档触发读取；逐帧渲染读取缓存。同轮请求合并，相同内容复用配置 revision。配置准备阶段编译类别倍率、关系 mask 和图参数；旧参数结算至切换时刻后，参数、连接绑定与相关资格集合在同一次提交中生效。

补齐旧 JSON 的文件名、字段、类型、导入/导出方向及缺省语义，并保留公开消费者所需格式。NG 的 L/R 状态使用独立版本 schema。旧传播概率字段保留兼容值，其解释写清楚。

用户编辑先校验，写同目录临时文件并替换，再走统一读取流程。配置缺失时使用并生成默认值；坏文件/写失败保留有效配置并报告结果。旧公开配置导入通过此入口落盘；本档声望转移则校验完整 pending 状态后一次提交。加载本档业务后采用当前配置 JSON。

交付要求：菜单编辑/关闭、外改文件后的 UI 刷新及读档应取得当前配置；A→B 和退出重进应共用设置，各档业务应独立恢复。逐帧渲染应读取缓存，配置读写由更新入口执行；无效输入应报告校验结果并保留有效配置，阈值、关系 mask 和图应同次提交。旧文件协议与配置 schema 应分别使用夹具验证；连接文件应采用稳定 key。
