项目目录：`E:/source/repos/SLSF Reloaded NG`。从[项目规格](../../../../.scratch/native-migration/spec.md)和本组任务书开始，需求或已选行为的更新先落到规格。

## 开工与分工

1. 检查 git status、前置组报告和现有头文件，确认本组实际缺口。
2. 对已有实现运行相关测试，随后按任务说明推进。
3. 按本组列出的 CPP、对应头/测试及必要构建项工作；共享工作区已有修改继续保留，共享定义在现有接口上衔接。
4. 外部源码按本任务实际用到的接口读取，实际采用版本及所有权写入证据。
5. 编写代码、测试、脚本或生成模板时执行 [AGENTS.md 的代码注释规则](../../../../AGENTS.md#code-comments)，默认零新增注释；仅在规则允许的必要例外下写最短说明。

`main.cpp/Lifecycle.cpp`由 06 组建立统一装配，后续适配器接入同一入口。

## 验证

用实际入口覆盖可观察结果。修 bug 时先复现，再修复并运行回归；随机失败保留 seed 和输入，解析失败保留语料。具体命令见[测试说明](00-native-testing.md)。

纯核心使用可控时钟/随机/提供方；引擎、VM 和提供方 ABI 由目标运行时 probe 支持。前置环境缺失时，完成可独立执行的部分，并在报告列明待接入接口及待验证项目。

## 交付

报告写到本组指定的 `docs/evidence/task-groups/` 路径，说明改了什么、命令及退出码、测试数量、seed/日志位置和下组接入点。已有报告追加有日期的本轮结果，保留历史结果。性能记录同时给出硬件、构建配置及输入规模。

更新项目路线中的实际状态，链接报告。保留原模板作者和许可文件。

交付前逐条检查本次 diff 中新增或修改的注释，删除复述代码、模板说明及其他不符合必要例外的内容；无新增注释是合格交付。
