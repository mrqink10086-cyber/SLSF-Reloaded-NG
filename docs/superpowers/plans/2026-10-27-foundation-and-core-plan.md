# A：核心与规则任务说明

[项目规格](../../../.scratch/native-migration/spec.md)定义需求及行为。本文件说明 A01–A08 的交付边界，模块分工见[清单](2026-10-27-task-books/manifest.json)。当前实现状态以项目路线及各组证据为准。

模块接口、状态归属及现有代码接入按[代码库设计](../../../.scratch/native-migration/design.md)。A03–A08 在 ReputationModel 内组合；数值行使用 WorldModel 解析出的 RegionId。

本轮采用的 owner/alias 编译、类别集合、对齐行、公开查询快照及 AVX2 执行方式统一见[优化实施方案](../../../.scratch/native-migration/optimization-plan.md)。先补 01/02 组的数据基础，再进入 03/04 组。

## A01 公开合同

从旧 PSC、PEX 和 ESP 提取函数、事件、类别、记录和 VMAD 绑定。区分公开承诺、批准改变及内部实现；记录实例/Global、默认参数、返回类型和 latent 属性。

已有清单为 124 个有效函数声明，其中公开 86 个；52 个输入事件、7 个回应、25 类、58 个记录中 57 个公开身份。保留原插件名、FormID、EDID、Quest/alias 和脚本绑定。修订清单时保留源文件哈希及可重复提取方法。

交付要求：提取器应生成合同规定的声明和资产身份；负向夹具应报告对应签名或资产偏差。StorageUtil、旧 JSON 和原始 SLSF 桥接的逐字段输出 schema 由 B06/B07 补齐。

## A02 共享类型与测试边界

核心静态库使用自有 DTO、数字 ID 和业务类型，使用标准 C++ 独立编译；游戏、VM、文件、时钟和随机数通过 ports 注入，对应外部类型由 adapter 转换。

共享边界覆盖 NumericCommand/Query、ProviderCommand、地点构建/绑定/归属、时间 Advance、配置校验及状态 Encode/Decode。已实现声明以头文件为准；扩展边界先对齐调用方，再开发模块。

VM port 提交异步请求并交回拥有自身数据的结果；引擎 port 把工作投递到合法上下文；WakeSource 启停唤醒源；随机 port 允许固定 seed。核心与游戏边界分开链接和测试。

交付要求：核心测试应能独立运行；假时钟、随机源和提供方应驱动实际公开入口；游戏边界应通过对应 port 接入。

本轮补充：统一 CategoryMask、RegionId 寻址、实际对齐的 32-double 行及纯配置 DTO/revision；区分 provider 事实与类别设置业务类型，并检查共享头能组合包含。为数值实现配置 AVX2/precise 编译，基础引导代码单独保留。验收按优化实施方案的 01 组执行。

## A03 数值状态与类别设置注册

实现显式写入、查询、局部/全局清理和提供者类别设置 OR。32 槽行存储 25 类 L/R，直接 Set 保持 Int32 精度；数值命令规则见项目规格。

NotReady/Stale 返回明确状态并保留本档类别设置。Missing/Incompatible 等确认失效撤销该提供者的类别设置。一次性待清理候选集合取 CumDump、Unfaithful、Cuck、Airhead；业务层确认内置来源缺失后执行清理。Disabled/Unregistered 沿用其显式撤销语义。

交付要求：同步返回后读到提交值；撤销时移除该模组自己的类别设置；暂时未知及恢复期间保留设置和计数；每个确认失效阶段生成一次四类清理候选；容量和无效输入返回约定状态。修复结果见[记录](../../evidence/2026-10-27-provider-readiness-fix.md)。

本轮补做：数值改为每个地区的声望数据，类别设置改为类别 mask 并保留 activeCounts；数值类别汇总与显式 flags 分开维护。拆开可变状态、公开查询快照和完整 Capture；发布应关联同一 revision 的映射和数值，持有中的快照应保留其发布内容。具体恢复及集合检查按 02 组要求执行。

## A04 地点与区域

实现静态地点父子森林、稳定身份、DFS 区间、运行时稠密索引、本档 owner 映射和公开 ApiLocationIndex。树用于归属，传播连接另建图。

归属按原 alias/自定义/默认区域规则解析；未单独注册的子地点归入所属地区声望数据。自定义区域注册、卸载及加载顺序变化保持稳定身份，无法绑定的记录进入 unresolved 集合。

交付要求：城市、室内及子地点应解析到原归属地区声望数据，独立区域应解析到自己的地区声望数据；环、重复身份及越界输入应返回定义错误；稳定身份往返应找到同一地区声望数据，既有大森林对照应继续通过。详细结构见[地点设计](../specs/2026-10-26-location-index-design.md)。

本轮补做：稳定键有序查找、canonical owner 编译、父先子后的全局优先级归并及规范化 alias 索引。保持当前优先级与公开索引规则，每个地区的声望数据迁移按稳定区域身份完成；具体步骤见优化实施方案的 02 组。

## A05 传播图与数值内核

当前状态：纯核心已实现，含 owner 投影、CSR 复用和 AVX2 传入/松弛；实现与验证见[03 整链实施报告](../../evidence/2026-10-28-03-chain-implementation.md)。

构建显式有向图及按目标组织的 CSR，校验权重、重复边、自环和稳定区域身份。0 表示关闭边，生产配置使用完整有效的权重；孤立区域允许存在。

内核职责分成计算传入目标、推进 R、兼容单跳脉冲。每步比较目标全部入边，同类取 max，应用每跳权重与门槛；冻结输入后写新行。标量参考和 AVX2 共用业务边界，填充槽保持屏蔽。

采用按类别连续加载和独立向量累加器，直接读取冻结 L/R；外层保留整批跳过，内层使用向量门槛。类别集合与数值行的配合按优化实施方案执行。

先选择简单推进实现并记录有效默认参数。指数松弛、细分步进等方案在出现具体误差或成本问题时再比较。算法选择、L/R 及公开映射见[传播设计](../specs/2026-10-26-weighted-reputation-diffusion-design.md)。

交付要求：25/20 应取 25，每跳应应用门槛，来源降低后应比较剩余入边，脉冲应执行一跳；孤立节点应按其本地及残余传入状态推进。相同输入下标量与 AVX2 的公开结果应符合相同规则，并记录代表性图上的成本。

## A06 增减与时间结算

当前状态：纯核心已实现事件时间分段、类型化规则、自定义地区标记和复用工作缓冲。会话在绑定、连接、配置或自定义地区注册更新时替换准备结果。

按原各入口实现 gain、默认/自定义地区 decay、倍率、保护和辅助时间状态。把原规则与 L/R 模型衔接：L 按旧规则处理，R 跟随传入目标；地点保护由本地增长续期，R 按传播规则独立推进。

由一个结算入口拥有已消费时刻，切分必要的保护/业务边界后统一提交。同一时刻重复推进应返回已结算结果；跳时推进数值和记忆，观测类计分处理实际事件。

共同时间系数移出类别循环，读取预编译类别参数；保留旧批量衰减的抽样次数和范围。保护期限及候选集合按优化实施方案维护。

交付要求：直接减值应反映到查询结果；保护到期及各衰减档位应按原规则处理；同一区间应消费一次，并按本地衰减→传播的顺序保留本批传入结果；等待、睡眠和正常推进应按对应业务边界结算。

## A07 原有玩法规则

分别实现匿名、可见性、目击、动画分类和评论的纯规则模块。输入为有 readiness 的快照，输出为数值命令或业务结果。

保留匿名三游戏小时及 `max(7, 2R-awayDays)` 记忆规则；身体槽位 32/45/49/56/58 与腰带规则；关系分组 `<0`、`0`、`1..3`、`>=4`；一次扫描最多一次成功。夜间与前戏同时成立才减半。P+ 角色、动作和注解用于判定实际交互，原动画开始宽限继续保留。

交付要求：典型和临界场景应来自旧源码；dirty 刷新应更新事实缓存，业务事件及原周期应驱动计分；未知事实应暂停依赖该字段的新计分。

候选条件使用入口各自的类别集合；自动目击用 selectedMask 去重，保持原候选顺序、随机调用及 50 次尝试规则。动画及显式入口分别执行自己的条件。

## A08 状态编码

实现有版本的完整本档状态 Encode/Decode。保存稳定身份、数值、类别设置、区域注册及其业务关系、保护和已结算时刻。用户设置和用户连接偏好由跨档配置 JSON 保存；进程缓存、引擎指针、协程及临时句柄留在运行时。

解码先构造 pending 状态并完整校验，成功后交给加载阶段绑定和激活。字段数量、尺寸、引用、版本和坏输入有明确边界。新增持久字段同步更新版本与往返用例。

派生 mask、编译 owner/alias、CSR 和 dirty 集合在恢复时重建；运行期布局压缩与持久 schema 变更分别处理，保留 v1 夹具及版本用例。当前 v1 的 settings/用户 graph edit 字段明确版本处理，激活采用当前 JSON；地区声望数据 Capture/Restore 接入按优化实施方案的 02 组完成。数据归属见[配置与菜单设计](../../../.scratch/native-migration/configuration-design.md)。

交付要求：完整往返应恢复捕获的业务值和类别设置，并结合当前配置重建类别汇总；截断、非法计数/值及未知版本应返回具体校验错误，缺失引用应进入 unresolved 集合。有效候选经完整绑定后提交，无效候选应保留当前已提交状态；相关解析器应能运行 ASan/模糊测试。
