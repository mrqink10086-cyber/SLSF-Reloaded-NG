# 外部集成状态与生命周期

本文解释[项目规格](../../../.scratch/native-migration/spec.md)中的状态边界，供 B03、C01 和各适配器使用。

## 状态归属

| 状态 | 例子 | 保存/失效方式 |
|---|---|---|
| 进程能力 | 已加载 DLL、API 版本、函数表及静态记录索引 | 进程复用，按提供方协议取得 |
| 角色/场景事实 | 装备、纹身、P+ 角色/交互、Actor 和临时句柄 | 本会话查询，dirty 或场景切换后刷新 |
| 跨档配置 | 用户设置、用户连接及 UI 偏好 | Configuration 读取 JSON 并通知消费者 |
| 本档业务 | 模组注册和类别设置、声望、区域及业务时间 | 原生保存/加载 |

分别记录插件是否安装、查询接口是否可用，以及当前角色数据是否就绪。模组注册和启用类别随本档保存，同类按 OR 合并。

## 能力查询

串行 Ensure 管理 Unqueried → Waiting → Available/Missing/Incompatible。并发使用方共用请求结果。先注册一次性广播监听，再尝试请求；后加载的能力按实际协议更新。

API 描述在进程内复用。角色结果复制为自有快照并注明 readiness，VM/JC 对象按实际所有权释放。外部调用在核心事务锁外执行。

## 暂时未知

NotReady 表示当前数据未就绪，Stale 表示当前事实需要刷新。两者保留模组注册和类别设置和既有声望，暂停依赖该事实的新计分；正常时间规则继续，恢复后不追补未知时段。

Missing/Incompatible 等确认失效可撤销对应提供者类别设置。CumDump、Unfaithful、Cuck、Airhead 的清理还要确认内置来源不存在且最后一个外部类别设置消失，再按失效阶段执行一次。其他类别不参与该自动清理。

## 启动与换档

1. 加载阶段注册 SKSE/提供方监听，检查 CPU/OS 能力并读取配置 JSON。
2. DataLoaded 构建静态记录索引并取得可查询的进程能力。
3. 新游戏建立默认本档状态；读档先关闭业务开关、递增 session epoch 并取消旧任务。
4. 解码 pending 业务状态，通过 Configuration 重读配置 JSON，按当前插件表和配置绑定稳定身份、重建本档映射；收集无法绑定的引用。
5. 完整状态激活后开放业务开关。角色事实重新读取，各适配器按 readiness 提供快照。

异步消息携带 session/index/scene epoch。读档、Revert、场景结束、加载失败或返回菜单后，已失效代次的结果被拒绝。一个执行器拥有协程帧和取消资源。

## 刷新与验证

装备和已验证外观事件置 dirty，在业务使用边界做有界刷新。刷新合并等待与业务计分各自调度。

核心验证未知→恢复保留类别设置、确认失效的四类候选和旧 epoch 拒绝。目标运行时验证监听时序、能力版本、A→B、加载失败、角色事实重建和资源释放。当前修正见[NotReady/Stale 修复记录](../../evidence/2026-10-27-provider-readiness-fix.md)。
