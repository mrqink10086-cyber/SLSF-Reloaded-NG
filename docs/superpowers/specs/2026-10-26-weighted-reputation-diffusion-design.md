# 声望传播：业务模型与执行结构

[项目规格](../../../.scratch/native-migration/spec.md)定义已选行为，A05/A06 实现图、内核和时间结算。本文把业务模型与工程选择分开，便于实现时沿同一边界验证。

## 业务模型

每区域每类保存本地值 L 和传入值 R，公开值 `F = max(L, R)`。实际本地行为及显式命令写 L；被动影响写 R，可继续传给下一跳。来源下降后，外地 R 随有效传入目标退去。

区域使用显式有向边。每条启用边有 `0 < retention < 1`；0 关闭边。对目标 t 的每一类别，从同一步快照计算：

```text
candidate(s → t) = retention(s → t) × max(L[s], R[s])
candidate < cutoff 时丢弃
incoming[t] = max(0, 全部保留的 candidate)
```

同类多来源取较大值：25 与 20 形成 25 的传入目标。当前较强来源下降后，其他有效来源仍可支撑目标。图外节点保持孤立；用户可编辑独立区域的连接。

R 根据实际经过时间向 incoming 推进。初版选择直接、有效的推进规则并记录参数，观察公开值是否满足逐跳、门槛、持续传播及来源退去的行为。

## 与原脚本的衔接

原版已经有固定默认候选关系；将其编译成数字边表属于执行优化。原版自动传播是概率触发、随机目标/类别，再把来源百分比加到目标。这里的持续推进、max 合并和来源跟随是已选定的结果模型改变。

增长、衰减档位和地点保护以原规则为基线，保留默认地区与自定义地区的差异。L 执行本地规则，R 执行传入推进，被动传播不续本地保护。一次时间结算统一提交结果；F 在提交后派生。

| 入口 | 双层状态操作 |
|---|---|
| 显式新值 V | `L=V, R=min(R,V)`；直接 Set 保留 Int32 范围 |
| Clear/Wipe | 指定范围 L/R 置零，清理相关本地保护 |
| ManualSpread | 使用旧源/目标/类别和 clamp 后的百分比，目标增量采用浮点计算；通过显式新值写入 |
| Spread/SpreadRoll | 先结算实际时间，冻结快照；受影响目标比较全部入边，`R=max(oldR,incoming)`，调用只做一跳 |

## 工程执行

- 每区域 32 个 double 槽，实际 25 类；每行 256 字节，对应 8 个 AVX2 向量。屏蔽填充槽。
- 按目标排列 CSR 入边，循环只做源行读取、边权乘法、门槛筛选和逐类 max。
- 一步只读同一快照，写入新行后统一发布。显式命令、自动结算和单跳脉冲复用计算边界。
- 以已结算时刻保证同区间只消费一次；保护到期等业务边界由 Settlement 拆分。跳时消费实际时间，观测事件保持原计分节奏。
- 初始标量参考用于对照 AVX2。指数松弛、进一步步进优化及收敛实验是工程备选，有具体问题时再比较并记录取舍。

## 验证

主要用例为：每跳衰减/门槛、25/20 取强、孤立节点、来源撤去与次强来源接替、显式下降、Clear 后未来实际传入、脉冲一跳、同区间重复查询、保护边界和跳时。代表性图记录运行成本。

默认权重、门槛及时间参数随实现提供有效配置。原始候选拓扑见[研究草案](../../research/default-reputation-topology.proposed.json)；其中空值需在采用时选定。项目完成标准以规格的可观察行为为准。
