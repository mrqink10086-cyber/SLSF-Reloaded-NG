# 地点索引与区域归属

本文解释[项目规格](../../../.scratch/native-migration/spec.md)中的地点结构。A04 实现索引/归属，A05 使用另建的传播图，B05 负责把保存的稳定身份绑定到当前运行时。

## 三种身份

| 身份 | 用途 | 生命周期 |
|---|---|---|
| 稳定 LocationKey/RegionKey | 插件身份及 local FormID、自定义区域持久身份 | 存档/配置 |
| 稠密运行时 ID | 连续数组、父子森林和 owner 查询 | 本次静态索引 |
| ApiLocationIndex | 原公开地点数组/列表次序 | 兼容映射 |

运行时 ID 可以随加载顺序和索引重建改变。保存稳定身份，加载后再映射；公开索引维护独立映射，保留原调用含义。

## 静态森林与本档映射

DataLoaded 收集 BGSLocation 及父子关系，构建并校验森林。用迭代 DFS 记录节点进入/退出区间，祖先判断使用区间包含。环、重复身份和非法引用在构建时处理。

静态索引在进程内复用。本档自定义区域、alias/owner 映射和公开注册可在读档后重建。先套用原归属优先级，再解析默认/自定义区域；普通子地点归到所属地区声望，显式独立注册才建立独立地区声望数据。

查询从已绑定的地点 ID 取得 owner RegionId；需要公开位置时转换 ApiLocationIndex。批次构建完成后发布一致视图，变更归属时同步更新 index epoch。

## 与传播图的关系

父子森林回答“这个地点属于哪个地区声望”。显式传播图回答“哪些区域可以相互传入声望”。树上父子关系不自动建立传播边；自定义区域的连接由默认配置或用户编辑决定。

## 保存与验证

保存区域的稳定身份和本档注册；加载后根据当前插件表重新绑定。缺失或无法解析的引用进入 unresolved 集合，能够绑定的状态完整激活。

通过城市/室内/子地点、alias、自定义独立区域、加载顺序变化和缺失引用检查公开结果。已有核心包含森林对照及 codec 往返测试，进度见[02 组报告](../../evidence/task-groups/02-state-location-and-codec.md)。引擎数据提取和游戏加载验证由 B04/B05 完成。
