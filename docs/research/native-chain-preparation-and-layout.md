# 地点、配置、时间与传播整链优化

日期：2026-10-28。本文继续[原生算法研究](native-algorithm-optimization.md)和[01–03 独立审核](../evidence/2026-10-28-01-03-independent-review.md)，回答 CSR 复用、小镇与自定义地区、查表、早退、内存连续性和指令集的后续问题。本文记录源码事实、局部测量与实施建议；项目需求由[规格](../../.scratch/native-migration/spec.md)维护。

本文保留研究时的源码状态与局部探针。随后 03 组已在现有逻辑中接入 owner 图投影、准备结果复用、类型化规则、自定义地区标记、工作缓冲和 AVX2 松弛；当前接口、真实 `Advance` 对照和回归结果见 [03 组交付记录](../evidence/task-groups/03-diffusion-and-settlement.md)。

## 优先改执行链

固定图应在地点绑定或连接变化时编译，`Advance` 消费已经绑定的数字图。下一步收益主要来自减少重复准备、字符串查询、复制和分配，再补连续数值计算。当前传播内核已经使用 AVX2，整个业务链仍有可移出热路径的工作。

建议的数据流为：

```text
加载/注册地区/配置更新
  → 稳定身份与 Location 森林
  → LocationId → 所属 RegionId、地区归属、公开 API 映射
  → canonical owner 图、CSR、自定义地区标记、类型化参数
  → 会话持有的只读准备结果

事件或到期任务
  → 数字 ID、开关与候选 mask 筛选
  → 在业务时间边界结算
  → 冻结来源 → 一跳传播 → 更新声望与汇总
  → 一次提交与公开快照
```

准备结果和可复用工作缓冲由现有 WorldModel / ReputationModel / Session 持有，继续使用单个业务执行器。

## 地点范围：已经有小镇，运行期绑定仍需接入

[默认图](../../src/core/reputation/DiffusionGraph.cpp)已有 **21 个节点、39 对双向连接、78 条有向边**。除各主城与 Raven Rock，还包含 Riverwood、Rorikstead、Ivarstead、Shor's Stone、Dragon Bridge、Karthwasten、Skaal Village，以及 Largashbur、Dushnikh Yal、Mor Khazgur、Narzulbur 四个兽人据点。

旧脚本的 42 个槽来自 21 个默认地点加 21 个自定义槽。它与当前图的 21 个默认节点是不同计数。旧资料对 major/minor 的分类存在注释与实际数组差异，绑定应核对稳定身份、实际数组和公开索引，名称清单本身不能替代这些绑定。

当前 C++ 核心能表达以下情况：

| 地点用途 | 地区归属 | 传播关系 |
|---|---|---|
| 城市里的室内、街区、普通子地点 | 继承城市的所属地区，共享声望 | 共用城市节点 |
| 城市树下、需要独立声望的自定义地区 | 注册独立地区，按 `customOrder` 的全局优先级确定归属 | 显式连接到城市或其他节点 |
| 独立城市或独立 Location 树 | 注册自己的稳定地区身份 | 显式配置连接；孤立节点也有本地声望 |
| 与另一个地区共用声望的注册地点 | owner 规则归并到同一地区 | 在所属地区图中处理 |

当前优先级选择全局最先的候选，子地点独立需要匹配注册顺序；Location 的父子关系与传播边分别配置。[RegionRegistry](../../src/core/location/RegionRegistry.cpp)已实现父先子后归属和数字直查。[插件入口](../../src/main.cpp)仍是初始化示例，游戏记录收集和完整 WorldModel 接线属于后续交付。

增加其他村庄或模组城市时，应给真正需要独立声望的聚落增加地区，保留既有公开索引的含义；室内和普通子地点继续映射到所属地区。这样计算规模随独立声望地区增长，而不是随全部游戏 Location 增长。

### 需要补齐图节点与 owner 的衔接

当前默认图构造器要求 21 个互异的稳定地区 key；`CompileDiffusionGraph` 按 `accountKeys` 找行，没有把端点转换到 canonical owner。若两个图节点共用一个 owner，提前转换 key 会被默认图构造器判重复；保留原 key 又可能让边落到没有实际地点使用的行。[地区绑定](../../src/core/reputation/ReputationState.cpp)目前也为每个已注册 key 分配一行。

建议准备阶段先形成按地区下标访问的 `canonicalOwnerByRegion`，再把语义图端点投影到所属地区：

1. 将来源和目标转换到所属 RegionId。
2. 将同地区连接视为地区内部关系，生成跨地区传播图时去掉自环。
3. 同一来源、目标出现多条边时取最大的非负系数，延续当前 `max(coefficient × F)` 聚合。
4. 生成 CSR，并一起保存公开 API 索引到所属地区的映射。

这是本轮提出的归并方案，实施时应覆盖“子地点共享”和“子地点独立”两组例子。地区共享与独立由玩法和注册规则决定；需要独立声望的村镇保持独立 owner。

## CSR：绑定一次，连续使用

当前 [Advance](../../src/core/reputation/Settlement.cpp) 在判断有无到期工作之前调用 `CompileDiffusionGraph`；[手动脉冲入口](../../src/core/reputation/Settlement.cpp)也重新编译，并按来源复制一份筛选后的 CSR。编译包含稳定 key 查找、排序和分配，这些工作应归入准备阶段。

复用范围由实际依赖决定：

| 变化 | 需要更新的准备结果 |
|---|---|
| 新游戏、读档、地区注册/移除、owner 或数字索引变化 | 地点映射、地区标记、图绑定及 CSR |
| 传播连接、方向或系数变化 | canonical owner 图及 CSR |
| 类别倍率、衰减档位或阈值变化 | 参数数组、相关类别资格；沿用拓扑与系数相同的 CSR |
| UI 显示偏好、普通声望数值变化 | 沿用已准备的地点和图 |

缓存身份应包含当前会话的绑定代次和图 revision。普通声望 revision 每次写入都变，适合发布声望，不能承担图复用的身份。由不可变准备结果持有 CSR 及其身份，输入边界建立完整性，内部连续调用使用该结果；现有可接收任意图的检查入口仍可供独立调用和测试使用。

来源受限的脉冲可以在现有 CSR 上使用来源位集合。小图先扫描入边并检查来源；来源很少且图明显扩大时，再比较附加出边索引生成受影响目标列表的收益。两种方式都可以省去每次分配筛选 CSR。

### 本机生产入口对照

本轮探针直接调用生产图编译与传播入口，复用组保留每次输出清零、完整图校验和相同 AVX2 计算。Clang 20.1、`-O2`、i5-13600KF，预热后取 7 轮中位数；默认组使用真实 21 节点拓扑，扩展组每节点有 3 条入边、3 条出边。

| 节点 / 有向边 | 每次编译＋计算，μs | 复用 CSR＋计算，μs | 局部比值 |
|---|---:|---:|---:|
| 21 / 78，默认图 | 4.339 | 0.285 | 15.24× |
| 128 / 384，合成图 | 40.080 | 2.130 | 18.81× |
| 512 / 1536，合成图 | 229.550 | 8.674 | 26.47× |

每种规模对 17 组变化输入比较全部 32 槽，重新编译、复用和标量计算逐位相同。测量是热数据的编译与传播阶段，未固定 P/E 核，完整 `Advance`、提交和发布由接入后的基准测量。方法、原始日志和复跑脚本见[探针报告](../evidence/algorithm-chain-research/chain-probe.md)。

归档脚本重新编译执行后同样通过；默认图测得 4.240 → 0.295 μs。512 地区的复用组第二次为 15.319 μs，首轮为 8.674 μs，说明本组扩展规模绝对耗时有波动；两次都支持移除重复编译。完整结果见[复跑日志](../evidence/algorithm-chain-research/chain-probe-replay.log)。

## 查表与早退按阶段安排

| 阶段 | 当前情况 | 建议的热路径 |
|---|---|---|
| 实际地点查询 | 稳定 key 排序二分；归属数组直查 | 当前地点不变时复用已解析 ID；绑定代次变化时重取。需要高频入口时比较连续 runtime FormID 数字索引 |
| 地区归属 | `locationOwners[LocationId]` | 保持 O(1) 数字寻址，公开 API 入口先映射到所属 RegionId |
| 自定义地区判断 | 每地区扫描 `customRegions` 并比较稳定 key | 绑定时编译 `customByRegion[RegionId]`，逐地区读取一个标记 |
| 类别与来源条件 | 已有多个语义独立的 CategoryMask | 合并本次入口需要的长期条件和事实 mask，空集合结束相应计分阶段 |
| 倍率和档位 | `GainRules` 部分路径读字符串 map、构造类别 key | 配置更新时生成 25 项倍率和 5 档 gain/decay cap；热循环只读数字数组 |
| 到期工作 | 每次排序命令，并扫描地区时钟 | 入队维护有序结构；既定三类时钟用连续期限堆，先看堆顶再取到期对象 |
| 本地衰减 | 遍历 25 类并逐项测试正值 | 没有到期周期时结束本地衰减；稀疏正值按 `localMask` 升序枚举 |
| 图传播 | 每目标扫描 CSR 入边、类别连续计算 | 无入边的目标省去入边运算；无合格来源时省去候选计算；目标已有 R 的时间演进照常处理 |

地点的大型外部 ID 空间适合紧凑索引；内部 LocationId / RegionId 数字数组已经稠密。runtime FormID 与稳定存档身份分别使用，避免按原始 32 位 FormID 分配巨型稀疏数组。

早退应作用于已确定没有工作的阶段：关闭新计分、暂缺外部事实、空候选分别结束对应的新计分；保存的声望继续执行既有时间规则。`NotReady/Stale` 保留已注册类别设置和声望。零声望目标可以接收传闻；本地没有正值时，remote 时钟和本地结算锚点仍按业务推进。

随机规则按原来的地区、类别和候选顺序执行，保护期完全覆盖的类别保持原跳过行为。`CategoryMask::ForEach` 已按位号升序枚举，可用于等价筛选；旧入口的重复抽样次数及最多 50 次尝试继续按原合同执行。

分支减少的优先方式是把不变条件移出循环、按数据决定是否执行整个阶段。稀疏数据使用位枚举；密集数值行使用连续循环或 SIMD。`[[likely]]`、全分支改条件选择和手写预取均应由热点测量决定。

隔离的成员查询探针中，21 个地区、5 个自定义地区，一批查询由 0.291 μs 降至 0.026 μs；512 个地区、128 个自定义地区，由 153.603 μs 降至 0.563 μs。空自定义集合时原扫描更便宜，适合在整批外层选择“全部默认”的路径。比较只包含成员查询，使用相同长插件名及固定命中分布，具体数据见[探针报告](../evidence/algorithm-chain-research/chain-probe.md)。

类别枚举也支持按稀疏度安排工作：512 个 mask、每个 1 位时，25 类扫描为 3.013 μs，升序置位枚举为 0.293 μs；25 位全开时两者约 7.45 μs。本组只测枚举，原有[数值更新探针](native-algorithm-optimization.md#本机补充探针)另测 SIMD 与置位枚举，混合策略按真实业务批次选择。

## 当前连续到什么程度

| 数据 | 当前布局 | 访问形态 |
|---|---|---|
| 单地区的 L/R/F | 每行 32 double、256 B、32 B 对齐 | 类别方向连续；25 个业务槽，余槽为 padding |
| 地点与地区映射 | vector 数字数组 | 映射本身连续且可直接下标访问 |
| CSR offsets、operands | 各自 vector | 每个目标的入边连续，来源行仍按 source ID 间接读取 |
| 所有地区的可变状态 | `vector<AccountState>` | 地区对象连续，但跨地区 L/R 行之间夹有 F、保护期、flags、时钟等字段 |
| 每轮快照 | 新建 L/R/incoming 行缓冲 | 数值连续，当前每轮仍有分配、全 State staging 和复制 |
| 稳定 key、配置 map、树构建 | string、std::map、嵌套 vector | 包含独立分配；多数可限制在准备或持久化阶段 |

因此，当前是**局部连续**。索引数组连续，也仍然可能访问间接来源；CSR 连续描述一张稀疏图，不能让任意拓扑的所有来源同时变成顺序读取。

本轮实际布局为 `AccountState=1120 B`、`NumericRow=256 B`，两者均 32 B 对齐；相邻地区的 L 行首相隔 1120 B。默认 21 个地区的 AccountState 数组为 23,520 B，两份 L/R 快照为 10,752 B。CSR 每个 Operand 为 16 B，其中 source 在偏移 0、double 系数在偏移 8；边描述改 SoA 是可测候选，当前数值工作集应与完整结算一起比较。

建议先让会话保留 `SettlementWorkspace` 的连续缓冲容量，把稳定 key、完整自定义注册记录和图移入已有的只读准备结果。工作缓冲与已发布快照分别持有数据。随后比较将 L/R/F、保护期与时钟拆成连续列的收益；迁移业务结构前先测真实结算的复制与提交成本。

另一项候选是每个时间阶段先生成一份 `FrozenF=max(L,R)`，入边内核每条边读取一行 F，代替重复读取 L/R 和求 max。[首轮四入边探针](native-algorithm-optimization.md#本机探针结果)中额外生成 F 持平或稍慢；仅在同阶段 F 已经生成、或来源复用明显增多时重新比较。冻结应在本阶段衰减完成后发生，直接使用衰减前的派生 F 会改变结果。

## 指令集和乱序执行

现有 AVX2 内核按一条边连续读取类别，并使用多个独立累加器，已经有利于乱序执行。继续优先考察远端回落、F/mask 重建等连续算术。`RelaxRemoteRows` 目前忽略 backend 参数，是否已有编译器自动向量化应检查目标对象，之后再比较显式 AVX2。

位集合使用标准 C++ `countr_zero` / `popcount` 表达意图；`ForEach` 已采用最低位枚举。25 类的 mask 能放进一个 uint32_t，主要工作是少访问数据。gather 针对离散元素，而当前一条来源边需要整行类别，连续 load 更贴合这个布局。

本机 13600KF 官方规格列出 AVX2。发布继续以既定 AVX2 数值单元为基线；POPCNT、BMI、FMA 的可用性和生成代码另行核对。MSVC 的 `/arch:AVX2` 可能生成额外标量扩展指令，目标对象与入口能力检查应对应。FMA 适合乘加，本传播主要是乘法后取最大；`/fp:precise` 继续保持既定运算语义。[Intel CPU 规格](https://www.intel.com/content/www/us/en/products/sku/230494/intel-core-i513600kf-processor-24m-cache-up-to-5-10-ghz/specifications.html)、[MSVC /arch](https://learn.microsoft.com/en-us/cpp/build/reference/arch-x64?view=msvc-170)、[MSVC /fp](https://learn.microsoft.com/en-us/cpp/build/reference/fp-specify-floating-point-behavior?view=msvc-170)。

## 实施顺序与验证目标

| 顺序 | 工作 | 归属 | 交付要求 |
|---|---|---|---|
| 1 | 按事件时间边界结算，统一命令时刻合同 | A06 | 复现审核中的单地区、初始 L=0、decayPerDay=2、固定最小 RNG 例子：Set10@0.5 后为 10，结算至 1.0 为 9 |

| 3 | 无到期工作早退；复用数值缓冲和有序任务结构 | A06/B01/B02 | 同时刻重复调用、空候选、时间跳跃按既定时钟/RNG 规则执行 |

| 5 | 绑定更多真正独立的村镇/模组城市并配置连接 | A04/B02/B07 | 稳定身份、旧 API 索引和共享/独立归属明确；读档重新绑定 |

前三项先减少整链工作量。后续布局和 SIMD 用真实工作负载选择。独立地区扩展继续保持固定连接、一跳衰减和同类多来源取强的玩法。

本轮资料与复跑入口见[研究证据目录](../evidence/algorithm-chain-research/README.md)，包含地点源码核对、CPU 官方资料和局部探针。以上为研究及实施建议，生产缓存、布局迁移和运行期接线仍按对应任务交付。
